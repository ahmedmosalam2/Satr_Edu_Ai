Vision

The Problem We Solve

Traditional e-learning is fundamentally broken. Students get identical content regardless of level, LLMs hallucinate course-irrelevant answers, and exams never adapt to individual weaknesses.

📚
One-Size-Fits-All
Every student receives identical materials, ignoring knowledge gaps and learning pace differences.
🤖
LLM Hallucination
General-purpose chatbots generate confident but factually wrong answers, not grounded in actual course content.
📊
Static Assessment
Exams are manually created, never adapt to performance, and fail to identify where each student struggles.
Our Answer: Satr Edu AI transforms any uploaded academic document — PDF, DOCX, PPTX, scanned image — into a fully interactive, context-aware intelligent tutor that knows exactly what the course material says, adapts to each student's proficiency in real time, and never hallucinates.
Target Users
  • Students: Personalized explanations, adaptive quizzes, immediate academic support
  • Teachers: Auto-generate exams, monitor analytics, upload course materials
  • Admins: Manage infrastructure health, user access, system content
  • Parents: Portal to track their child's academic progress and risk levels
Educational Science Embedded
  • Spaced Repetition: Reviews scheduled precisely when student is about to forget
  • Item Response Theory (IRT): Mathematical ELO rating updates based on question difficulty
  • Socratic Method: AI agent guides students to discover answers through targeted questions
  • Hybrid RAG: Every answer strictly grounded in uploaded academic materials

LLM-Specific Vulnerabilities Addressed
Prompt Injection Defense
System/Context/User demarcation tags physically separate instructions from user input. Intent classifier acts as input filter — off-topic queries never reach main LLM.
RAG Poisoning Defense
Context chunks validated and cleaned before embedding. Cross-Encoder reranker filters irrelevant or malicious snippets before LLM generation.
Security Measures
  • Magic Byte Validation: File uploads validated by content headers (python-magic), not extension
  • File Size Limit: MAX 50MB enforced — prevents DoS attacks
  • Path Sanitization: Blocks directory traversal (../../etc/passwd)
  • Python Sandbox: subprocess isolation, 3s timeout, env vars scrubbed
  • RBAC: Depends(require_role(["teacher"])) on every protected route
  • CORS: Whitelist-only origins; blocks third-party requests
  • Stateless JWT: No DB lookup per request — role from token payload

Celery Task Limits
  • Soft timeout: 10 minutes → graceful warning + save progress
  • Hard timeout: 11 minutes → force terminate
  • Retries: 3 attempts with exponential backoff

Why 202 Accepted?
Heavy jobs (OCR + embedding) can take minutes. Returning 202 immediately keeps the UI responsive. The client polls /task/{task_id} or receives SSE status updates when complete.

Tesseract Preprocessing Pipeline
  1. Convert image to grayscale (L mode)
  2. Enhance contrast ×2.0 (ImageEnhance)
  3. Apply sharpening filter (ImageFilter.SHARPEN)
  4. Upscale to minimum 1000px width (LANCZOS)
  5. Binarize: pixel >140 → white, else black
  6. Tesseract PSM 6 (ara+eng → eng fallback)
Document Intelligence

Structure-Aware Chunking Strategies

How we split documents directly determines retrieval quality. We implement two strategies — naive for speed, structure-aware for accuracy.

📏 Strategy 1: Naive Recursive Splitting
Fast baseline. Works on all file types. Good for simple docs.
Separator Cascade:
Paragraphs
(\n\n)
→
Lines
(\n)
→

(. )
→
Words
(space)
⚠️ Can split tables and bullet lists across chunk boundaries — hurts RAG quality for structured docs
🏗️ Strategy 2: DeepDoc Layout-Aware
Inspired by RAGFlow. Preserves semantic units. Superior RAG accuracy.
  • Header Detection: PyMuPDF font-size + bold flags + Arabic regex (أولاً, الفصل) + English numbered headings
  • Table Preservation: Entire table extracted as one atomic chunk — row associations intact
  • List Grouping: Consecutive bullet items combined into a single contextual chunk
  • Context Prepending: Section heading prepended to each sub-chunk for retrieval relevance
✅ Dramatically improves RAG accuracy for structured academic PDFs and presentations
Arabic Text Reconstruction — A Critical Engineering Step
The Problem: Arabic characters change shape based on position in a word (initial, medial, final, isolated). Raw PDF text extraction outputs isolated letters in wrong order — completely unembeddable.

Step 1: arabic_reshaper.reshape(text) — Combines letters into correct positional forms (Arabic reshaping algorithm)
Step 2: bidi.algorithm.get_display(reshaped) — Resolves RTL/LTR bidirectional character ordering per Unicode BiDi standard
Semantic Intelligence

Vector Database & Embedding Architecture

Embedding Pipeline
Chunk text extracted from document
↓
Cohere embed-multilingual-light-v3.0
type=DOCUMENT for indexing, type=QUERY for search
↓
384-dimensional float vector generated
↓
Upsert to: collection_384_{project_id}
deterministic ID: {project_id}_{file_id}_{order}
↓
Payload: text, chunk_id, page, source_file, order
Why Cohere embed-multilingual-light-v3.0? Natively supports Arabic + English in a shared vector space. A single model handles all bilingual academic content without switching models. 384 dims = memory-efficient with strong accuracy.
Qdrant Collection Design
  • Naming: collection_{dim}_{project_id} — isolates per-course vectors at DB layer
  • Multi-tenant: Queries physically cannot cross project boundaries
  • Distance: Cosine Similarity — direction-based, normalizes for text length variation
  • Index: HNSW (Hierarchical Navigable Small World) — O(log N) nearest neighbor search
  • Upsert: Deterministic IDs ensure no duplicate vectors on re-index

AI Architecture

Multi-Agent ReAct Orchestration System

Not a chatbot — a coordinating intelligence. Intent classification routes each query to a specialized agent persona with custom tools and unique behavioral constraints.

🔍
RAG Agent
Multi-step query decomposition. Breaks complex questions into sub-queries. Loops through vector DB. Merges citations from multiple documents. Calls Calculator for math.
🎓
Tutor Agent
Adapts explanation depth to student proficiency. Beginner: analogies + step-by-step. Advanced: technical formalism + edge cases. Bilingual: TUTOR_PROMPT_AR / EN.
🏛️
Socratic Agent
FORBIDDEN: direct answers. REQUIRED: one guiding question per turn. After 2 wrong attempts: subtle hint. Never reveals final answer. Pure Socratic method.
📝
Quiz Agent
Generates N questions from recent context. Outputs structured JSON: question, options, correct_answer, hints. Validates with regex. Temperature 0.7 for variety.

AI Routing

Intent Classification Engine

The routing brain of the system. Before any heavy LLM processing, the Orchestrator classifies what the student actually needs — with Arabic and English support.

LLM-Based Classification
// System Prompt instructs LLM to return JSON: { "intent": "research | tutor | quiz | greeting | off_topic | concept_map | python_scratchpad | socratic", "confidence": 0.92, "reasoning": "User asked to explain...", "entities": ["Newton's 2nd law"] } // Regex strips markdown wrappers before parse // Confidence >= 0.5 → route to specialist agent // Confidence < 0.5 → default to RAGAgent (safe)
Routing Logic: If confidence ≥ 0.5 → specialized agent. Otherwise → RAGAgent handles safely with grounded factual search. This prevents classification errors from degrading user experience.

Post-Generation Validators
🔍 Validator 1: Answer Key Verification
Checks correct_answer key exists in options list. Mismatched questions silently discarded — never shown to students.
⚖️ Validator 2: A-Bias Prevention
LLMs systematically place correct answer as "A". Filter checks key distribution. If biased → redistributes correct positions across A, B, C, D randomly.

When LLM hits token limit mid-JSON: _repair_truncated_json() extracts all fully-formed question objects. Partial exams salvaged, not discarded.

Software Engineering

Design Patterns & Engineering Principles

Enterprise-grade software engineering discipline — not just functional code, but maintainable, scalable, and testable architecture built to SOLID principles.

🏭
Factory Pattern
LLMProviderFactory, ParserFactory, ChunkerFactory. Add new provider = one class. Zero changes to callers. Open/Closed Principle in practice.
🔌
Dependency Injection
FastAPI Depends() for auth, DB clients, LLM providers. Testable, composable, zero global state. Resources pooled once at startup event.
📦
Domain-Driven Design
routes/, controllers/, models/, agent/ — each directory owns exactly one domain. No cross-domain dependencies without explicit interfaces.
🔄
ReAct Agent Pattern
Agents are not hard-coded pipelines — they autonomously decide which tools to call at runtime based on reasoning. Flexible, extensible, debuggable.
🛡️
Active Record + DAO
Model classes encapsulate both Pydantic schema and Motor DB operations. Consistent insert_one / find / update interface across all entities.
📡
Message Bus / Observer
MessageBus logs agent transactions. Orchestrator observes results. Decoupled communication enables full tracing without coupling agent internals.

Engineering Journey

Key Challenges & Engineering Solutions

⚠️
Arabic PDF Garbling
Arabic letters extracted in wrong order, isolated, or reversed — completely unembeddable and unsearchable.
Solution: arabic_reshaper (positional letter forms) + python-bidi (Unicode BiDi algorithm) run on every extracted text block before embedding.
⚠️
LLM JSON Truncation
Large exam generations hit token limits mid-JSON, causing parse failures and 500 errors returned to teachers.
Solution: _repair_truncated_json() uses regex to extract all fully-formed question objects from broken payload. Partial exams salvaged.
⚠️
Table Splitting in RAG
Naive chunking split table rows across chunks, breaking data associations and producing nonsensical RAG context for the LLM.
Solution: DeepDoc structure-aware chunker detects table grids from PDF coordinates and preserves entire tables as atomic chunks.
⚠️
Async Event Loop Blocking
Synchronous OCR and LLM SDK calls blocked FastAPI's event loop, causing all concurrent requests to stall.
Solution: Celery offloads all heavy processing. Sync SDK calls wrapped in asyncio.to_thread(). Event loop stays responsive.
⚠️
LLM Exam Answer A-Bias
LLMs systematically placed the correct answer as option "A" in 70%+ of generated MCQ questions — easily exploitable.
Solution: Post-generation validator checks key distribution. If bias detected → redistributes correct positions across A, B, C, D.
⚠️
Multi-tenant Vector Leakage
Single Qdrant collection would allow course A's vectors to appear in course B's search results — a privacy and accuracy failure.
Solution: Per-project collections named collection_{dim}_{project_id} physically partition vectors at the database layer.

AI Engineering

Prompt Engineering Strategy

Prompt engineering is not an afterthought — it is the interface between software and intelligence. Every prompt is a deliberate engineering decision with measurable consequences.

Hallucination Prevention Prompt
<SYSTEM> You are an expert academic tutor. Rules (MUST follow strictly): 1. Answer ONLY from provided documents. 2. If answer not in context → say exactly: "I cannot find this in course materials." 3. Never extrapolate or assume facts. 4. Cite every factual claim: [Doc X] 5. Maintain full academic integrity. </SYSTEM> <CONTEXT> --- DOCUMENT [Doc 1] --- Source: physics_ch1.pdf (Page 4) {chunk_text} </CONTEXT> <USER>{student_query}</USER>
Prompt Injection Defense: SYSTEM/CONTEXT/USER tags physically separate instructions from user input. A user typing "ignore all previous instructions" cannot escape the <USER> zone.
Agent-Specific Prompt Strategies
Tutor Prompt Strategy
Adapts depth to student mastery level. Beginner: real-world analogies + step-by-step. Advanced: technical formalism + edge cases. Bilingual templates: TUTOR_PROMPT_AR / TUTOR_PROMPT_EN.
Socratic Prompt Constraints
FORBIDDEN: giving direct answers. REQUIRED: ask exactly ONE guiding question per turn. After 2 failed attempts: provide a subtle hint. Temperature: 0.6 (some creativity in questioning).
Exam Generation Prompt
FORBIDDEN: questions about page numbers, dates, copyright. REQUIRED: model answer per question. Temperature 0.7 for variety. Strict JSON schema enforced with 3 validators.
Temperature Strategy
RAG answers: T=0.2 (factual accuracy). Exam generation: T=0.7 (question variety). Socratic: T=0.6 (creative guiding). Intent classification: T=0.1 (deterministic routing).

  • Multi-Agent Architecture: ReAct-based agents collaborate to solve complex student queries — not a simple chatbot wrapper
  • Hybrid Search System: Dense + Sparse + Cross-Encoder provides state-of-the-art retrieval accuracy
  • Adaptive Learning Engine: IRT + ELO + Spaced Repetition matches academic testing research standards

  • Bilingual Support: Arabic + English handled natively across OCR, embeddings, classification, and UI
⚠️ Known Weaknesses (Identified & Planned)
  • Cold-Start Latency: Local OCR + embedding models on CPU-only hardware cause initial delays → GPU deployment planned
  • File Storage: Relying on filesystem storage limits horizontal scaling → AWS S3 migration planned
  • Evaluation Framework: LLM-as-a-judge is not standardized → Ragas / TruLens integration roadmapped
  • No Caching Layer: Repeated identical queries trigger full RAG pipeline → Redis semantic cache planned
  • Text-Only Retrieval: Cannot reference diagrams or equations from lecture slides → Vision RAG roadmapped
  • Progress Tracking: Limited to test scores → engagement metrics (read time, search frequency) planned
Overall Assessment: The project goes beyond simple API wrappers. It implements a robust, self-hosted system that solves real-world educational challenges. Its multi-agent architecture, mathematical learning models, and engineering rigor make it a standout senior software engineering project.
